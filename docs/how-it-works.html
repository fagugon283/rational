1 · 課題と市場のすき間

When several AI agents — from different vendors — work on the same code, the why gets lost: why a function exists, what was decided and rejected, what the team learned. Context evaporates between sessions and between agents, and tokens are wasted reloading history.

Cuando varios agentes de IA —de distintas compañías— trabajan sobre el mismo código, se pierde el porqué: por qué existe una función, qué se decidió y descartó, qué aprendió el equipo. El contexto se evapora entre sesiones y entre agentes, y se malgastan tokens recargando historia.

当来自不同厂商的多个 AI 智能体在同一份代码上协作时，"为什么" 会丢失：某个函数为何存在、做过和否决过哪些决定、团队学到了什么。上下文在会话之间、智能体之间消散，并因反复加载历史而浪费 token。

異なるベンダーの複数の AI エージェントが同じコードで作業すると、「なぜ」が失われます。ある関数がなぜ存在するのか、何を決め何を却下したのか、チームが何を学んだのか。コンテキストはセッション間・エージェント間で蒸発し、履歴の再読み込みでトークンを浪費します。

Competitors cover isolated pieces, but none solve the whole neutrally:

La competencia cubre piezas sueltas, pero ninguna resuelve el conjunto de forma neutral:

竞品只覆盖了零散的部分，但没有一个以中立方式解决整体：

競合は個別の断片を扱いますが、全体を中立に解決するものはありません。

Every non-trivial choice is recorded as an ADR-style file with fixed sections. The system returns an id (e.g. D-7f3a2c) that is embedded in the code.

Cada elección no trivial se registra como un fichero estilo ADR con secciones fijas. El sistema devuelve un ID (p.ej. D-7f3a2c) que se incrusta en el código.

每个重要选择都记录为ADR 风格的文件，包含固定小节。系统返回一个 ID（如 D-7f3a2c）嵌入到代码中。

重要な選択はすべて、固定セクションを持つ ADR 形式のファイルとして記録されます。システムは ID（例：D-7f3a2c）を返し、それをコードに埋め込みます。

// @why: D-7f3a2c
export function issueToken(user) { /* ... */ }

The comment is stable: it survives re-edits and any agent understands it. Decision ids are random 6-hex (no central counter → no collisions between parallel agents); tasks and learnings use sequential ids under a lock.

El comentario es estable: sobrevive a reediciones y lo entiende cualquier agente. Los IDs de decisión son hex aleatorio de 6 (sin contador central → sin colisiones entre agentes en paralelo); tareas y learnings usan IDs secuenciales bajo bloqueo.

该注释是稳定的：经得起再次编辑，任何智能体都能理解。决策 ID 为 6 位随机十六进制（无中心计数器 → 并行智能体之间不冲突）；任务与学习在加锁下使用顺序 ID。

このコメントは安定しており、再編集にも耐え、どのエージェントも理解できます。決定 ID は 6 桁のランダム 16 進数（中央カウンタ不要 → 並行エージェント間で衝突しない）。タスクと学習はロック下で連番 ID を使います。

5 · Hash traceability (take a function, find its why)

5 · Trazabilidad por hash (coge una función, encuentra su porqué)

5 · 哈希溯源（拿一个函数，找到它的"为什么"）

5 · ハッシュ追跡（関数から「なぜ」を引く）

When a function is tagged, the system stores a SHA-256 of its (normalized) body in registry.json — insensitive to reindentation, sensitive to real changes. This enables reverse lookup by location or by hash, and drift detection.

Al etiquetar una función, el sistema guarda en registry.json un SHA-256 del cuerpo (normalizado): insensible a reindentación, sensible a cambios reales. Habilita la búsqueda inversa por ubicación o por hash, y detección de deriva.

给函数打标签时，系统会在 registry.json 中保存其（归一化后）函数体的 SHA-256：对重新缩进不敏感，对真实修改敏感。由此支持按位置或按哈希的反向查找，以及漂移检测。

関数にタグを付けると、システムは（正規化した）本体の SHA-256 を registry.json に保存します。インデント変更には鈍感で、実質的な変更には敏感です。これにより位置またはハッシュによる逆引きと、ドリフト検出が可能になります。

rational-agnostic why src/core/lock.ts withLock      # function -> why
rational-agnostic why --hash <sha256>                # hash -> why

Instead of dumping all history, get_context assembles a minimal relevant bundle: the active task, the most relevant decisions and learnings (semantic ranking) and a tail of shared memory, trimmed to a token budget.

En vez de volcar todo el historial, get_context arma un paquete mínimo relevante: la tarea activa, las decisiones y learnings más afines (ranking semántico) y una cola de memoria compartida, recortado a un presupuesto de tokens.

与其倾倒全部历史，get_context 会组装一个最小相关包：当前任务、最相关的决策与学习（语义排序），以及一段共享记忆末尾，并裁剪到 token 预算内。

履歴をすべて投入するのではなく、get_context は最小限の関連束を組み立てます。現在のタスク、最も関連する決定と学習（意味的ランキング）、共有メモリの末尾を、トークン予算に収まるよう切り詰めます。

rational-agnostic context --task T-0001 --budget 1500

Semantic search uses local embeddings by default (all-MiniLM-L6-v2, no API key, offline); if the optional dependency is absent, a deterministic lexical fallback keeps search working. The vector index is a rebuildable cache (reindex); the markdown files are the source of truth.

La búsqueda semántica usa embeddings locales por defecto (all-MiniLM-L6-v2, sin API key, offline); si la dependencia opcional no está, un fallback léxico determinista mantiene la búsqueda. El índice vectorial es una caché reconstruible (reindex); los ficheros markdown son la fuente de verdad.

语义搜索默认使用本地向量嵌入（all-MiniLM-L6-v2，无需 API key，离线）；若缺少该可选依赖，确定性的词法回退仍可工作。向量索引是可重建的缓存（reindex）；markdown 文件才是事实来源。

意味検索は既定でローカル埋め込み（all-MiniLM-L6-v2、API キー不要・オフライン）を使います。任意依存が無い場合は決定的な字句フォールバックで検索を維持します。ベクトル索引は再構築可能なキャッシュ（reindex）で、正本は markdown ファイルです。

8 · Learning (the system improves)

8 · 学習（システムが良くなる）

A hybrid knowledge layer: agents record explicit learnings when they spot something reusable (record_learning), and a deterministic distill mines decisions for recurring patterns and reversals. So before deciding, an agent consults what was learned and avoids repeating reasoned-through mistakes.

Capa de conocimiento híbrida: los agentes registran learnings explícitos cuando detectan algo reutilizable (record_learning), y un distill determinista mina las decisiones en busca de patrones y reversiones. Así, antes de decidir, un agente consulta lo aprendido y no repite errores ya razonados.

混合知识层：智能体发现可复用之物时记录显式学习（record_learning），确定性的 distill 从决策中挖掘重复模式与反转。于是在决策前，智能体会先查阅所学，避免重蹈已被论证过的覆辙。

ハイブリッドな知識層：再利用できる気づきがあればエージェントが明示的に学習を記録（record_learning）し、決定論的な distill が決定から反復パターンや方針転換を抽出します。決定前に学びを参照し、検討済みの失敗を繰り返しません。

Key point: the tool does not understand your code by itself — the LLM does. The split:

Punto clave: la herramienta no entiende tu código por sí sola —eso lo hace el LLM. El reparto:

关键：工具本身并不理解你的代码——理解由 LLM 完成。分工如下：

要点：ツール自体はコードを理解しません——理解するのは LLM です。役割分担：

  • The tool (deterministic): adopt inventories the repo (languages, manifests, entry points, largest files, tag coverage) and emits a plan + onboarding prompt.
  • The agent you choose: reads the inventory and AGENTS.md, explores, and does record_decision + tag_code incrementally.
  • La herramienta (determinista): adopt inventaría el repo (lenguajes, manifiestos, puntos de entrada, ficheros grandes, cobertura de tags) y genera un plan + prompt de onboarding.
  • El agente que elijas: lee el inventario y AGENTS.md, explora y hace record_decision + tag_code de forma incremental.
  • 工具（确定性）：adopt 盘点仓库（语言、清单文件、入口、最大文件、标签覆盖率）并生成计划 + 上手提示词。
  • 你选择的智能体：阅读盘点与 AGENTS.md，进行探索，并增量执行 record_decision + tag_code。
  • ツール（決定的）：adopt がリポジトリを棚卸し（言語・マニフェスト・エントリ・最大ファイル・タグ網羅率）し、計画＋オンボーディング用プロンプトを出力。
  • 選んだエージェント：棚卸しと AGENTS.md を読み、探索して record_decision + tag_code を段階的に実施。

Integrity: the agent is forbidden from inventing rationale. If it cannot infer something, it writes a question to shared memory and asks you. init is non-destructive and verify does not fail on untagged legacy code.

Integridad: el agente tiene prohibido inventar porqués. Si no puede inferir algo, lo anota como pregunta en memoria compartida y te consulta. init es no destructivo y verify no falla por código legacy sin etiquetar.

诚信：智能体禁止编造理由。若无法推断，便在共享记忆中写下问题并询问你。init 不具破坏性，verify 不会因未打标签的遗留代码而失败。

整合性：エージェントは根拠の捏造を禁止されています。推測できなければ共有メモリに質問を書き、あなたに尋ねます。init は非破壊的で、verify は未タグのレガシーコードでは失敗しません。

10 · verify: teeth in CI and pre-commit

10 · verify: los dientes en CI y pre-commit

10 · verify：CI 与 pre-commit 中的"牙齿"

10 · verify：CI と pre-commit での「歯」

Deterministic checks whose severity you choose in config.json: orphan tags (pointing at a missing decision), anchors to vanished files, invalid task status, empty "Why". It exits non-zero on errors, so it fits a hook or pipeline. A .rationalignore excludes fixtures and examples.

Comprobaciones deterministas cuya severidad decides en config.json: tags huérfanos (apuntan a una decisión inexistente), anclas a ficheros desaparecidos, tareas con estado inválido, "Why" vacío. Sale con código ≠ 0 ante errores, así que encaja en un hook o pipeline. Un .rationalignore excluye fixtures y ejemplos.

确定性检查，其严重级别由你在 config.json 中决定：孤立标签（指向不存在的决策）、指向已消失文件的锚点、无效的任务状态、空的 "Why"。出错时以非零码退出，适配钩子或流水线。.rationalignore 可排除夹具与示例。

config.json で深刻度を選べる決定的チェック：孤立タグ（存在しない決定を指す）、消えたファイルへのアンカー、不正なタスク状態、空の "Why"。エラー時は非ゼロ終了するため、フックやパイプラインに適合します。.rationalignore でフィクスチャや例を除外できます。

rational-agnostic verify   # OK — 0 error(s) / exit 1 on failure

Persistencia en inglésBase de conocimiento buscable y portable entre agentes y en el tiempo
AGENTS.md genéricoPortable y sin filtrar el dominio del proyecto; el porqué vive en las decisiones
Aplazar daemon central y autotraducciónMenos complejidad; el agente escribe inglés mejor que un traductor empotrado
决策为什么
位于框架之上的层，而非框架空白在于一个中立、可移植的记录；保持确定性可维护诚信
稳定的 @why 标签+ 注册表中的哈希标签经得起编辑；SHA 支持反向查找与漂移检测
文件 + 加锁（无服务器）可随 git 移植，跨厂商智能体无需基础设施即可协作
默认本地向量嵌入离线、免费、私密；忠于 "agnostic" 之名；提供方可插拔
以英文持久化跨智能体、跨时间皆可检索、可移植的知识库
通用 AGENTS.md可移植且保护隐私；项目理由存于决策之中
推迟中央守护进程与自动翻译更低复杂度；智能体写英文优于内置翻译器
決定理由
フレームワークの上位の層であり、フレームワークではないすき間は中立で可搬な記録。決定的に保つことで整合性を維持
安定した @why タグ＋レジストリのハッシュタグは編集に耐え、SHA が逆引きとドリフト検出を可能にする
ファイル＋ロック（サーバー不要）git で可搬、ベンダー横断のエージェントがインフラ無しで協調
既定でローカル埋め込みオフライン・無料・プライベート。「agnostic」の名に忠実。プロバイダは差し替え可能
英語で永続化エージェント横断・時間横断で検索可能・可搬な知識ベース
汎用の AGENTS.md可搬でプライバシーを保つ。プロジェクトの理由は決定に置く
中央デーモンと自動翻訳を見送り複雑さを低減。内蔵翻訳よりエージェントが英語を書く方が良い
